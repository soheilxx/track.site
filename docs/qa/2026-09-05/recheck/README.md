## 3. What remains (and why)

- **Mobile LCP and performance are better but still above the targets** (LCP 2.9–4.0 s vs ≤ 2.5 s; performance 87–94 vs ~95; single runs, so ±5 points of noise). The remaining cost is the JavaScript that hydrates every marketing page (16 files, 217–231 KB gzip; `network-requests` of the re-check reports) and the HTML size (94–107 KB transfer). What was not changed and why:
  - The 13.6 KB flagged as legacy polyfills (`Array.prototype.at`, `flat`, `Object.hasOwn`, …) are Next.js's own `@next/polyfill-module`, required unconditionally by `next/dist/client/app-globals.js` (line 6) regardless of `browserslist` (`getSupportedBrowsers` only steers SWC targets). Removing them means patching Next.js.
  - The 22–29 KB "unused" bytes of the shared chunk are React DOM / Next runtime code, not application code.
  - The pricing DOM (2 251 nodes) renders the comparison matrix twice (desktop table + mobile accordion). A single responsive rendering is a design change of the matrix, outside a fix task.
  - Render-blocking CSS (24 KB gzip, "Est savings 320–520 ms") is one stylesheet for the whole site; splitting it needs per-route CSS, which Tailwind v4 does not produce.
- **`/en/login` SEO 63** (`is-crawlable`): the page is deliberately `noindex`; expected. **`/app` SEO 54**: authenticated dashboard, `noindex`; expected.
- **Hyphenation of demo tile labels at 320 px** (nl "Geaccepteerd", es "Entregados", de "Angenommen") relies on `hyphens: auto`; engines without a dictionary for the locale break the word at an arbitrary point instead. The label is complete either way (nothing is painted under the next tile).
- The recheck sweep covers the routes named in the findings (6 dashboard routes at all six widths, home in six locales, pricing in four, the article in en/de) plus the remaining 12 dashboard routes at 320/375/768 (`sweep-remaining-dashboard-routes.log`); the other public routes were not re-swept (unchanged code paths apart from the footer and the fonts).
