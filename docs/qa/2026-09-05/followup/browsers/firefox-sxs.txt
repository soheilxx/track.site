  browserType.launch: spawn UNKNOWN
  <launching> …\firefox-1538\firefox\firefox.exe -no-remote -headless -profile … -juggler-pipe -silent

Installation state (ls, grep -a on the binaries):
  INSTALLATION_COMPLETE and DEPENDENCIES_VALIDATED markers present; 53 files; firefox.exe 721 920 B, mozglue.dll 658 432 B, xul.dll 178 833 920 B
  firefox.exe embeds 3 <assemblyIdentity> entries incl. a <dependentAssembly> on name="mozglue"; mozglue.dll embeds its own
  assemblyIdentity name="mozglue" — the private assembly the OS reports as "not found" is present next to the executable.
  `pnpm --filter @track-site/web exec playwright install firefox webkit` exits 0 without downloading (playwright-install.log):
  the registry already holds the expected revisions firefox@1538 and webkit@2336 (playwright-core/browsers.json).

Assessment: the activation-context generation fails on this Windows installation for a correct private assembly — the same
symptom the full Playwright Chromium (chrome-win64) shows here ("Side-by-Side-Konfiguration ungültig", docs/16 §6.3), while
chrome-headless-shell and WebKit (Playwright.exe, no SxS dependency on a private assembly) start. A forced re-download was not
attempted: the binaries are intact and the failure is in the OS, not in the download. Firefox evidence needs another machine
(or the Linux CI runner of defect D14). A system Firefox exists (C:\Program Files\Mozilla Firefox\firefox.exe) but Playwright
can only drive its own patched build.
