# Tracking Knowledge — authoring guide

How an article in `apps/web/content/knowledge/{locale}/*.mdx` is written so that the article template (`apps/web/src/app/[locale]/tracking-knowledge/[slug]/page.tsx`, components under `apps/web/src/components/marketing/knowledge/article/`) renders it correctly. Binding rules from the redesign supplement §6: "Tracking Knowledge" is the product name in every language, the brand is "Track", English and German only for now, no invented authors, reviews, popularity numbers or success rates.

## 1. Files, groups and slugs

- One topic = one `translationGroupId` (the English file name). Every locale version lives in its own directory (`en/`, `de/`, …) and should use the same file name; it may set its own `slug` (URL segment, `^[a-z0-9-]{3,120}$`).
- Only `status: "published"` versions are listed, indexed, linked as hreflang alternates and accept feedback. `draft`, `translated` and `reviewed` are invisible to the public.
- The loader is `apps/web/src/lib/knowledge.ts`; template-only fields (`takeaways`) are read by `apps/web/src/lib/knowledge-article.ts`.

## 2. Front matter

| Field | Required | Rendered where |
| --- | --- | --- |
| `title`, `description` | yes | h1 and intro paragraph; `description` is also the meta description and the JSON-LD `description` |
| `excerpt` | no | hub cards and related-article lists (falls back to `description`) |
| `translationGroupId`, `slug`, `status` | yes | routing, hreflang, feedback |
| `topic` (one of the nine topic ids), `contentType` (`guide`, `tutorial`, `reference`, `explainer`, `update`), `level` (`beginner`, `intermediate`, `advanced`) | yes | meta line under the breadcrumbs, filters, JSON-LD type (`TechArticle` for `reference`/`tutorial`, `BlogPosting` otherwise), the contextual Track CTA (chosen by `topic`) |
| `platforms[]`, `shopSystems[]`, `tags[]` | no | filters and the related-article ranking (same topic first, then shared tags, then shared platforms/shop systems) |
| `author` | yes | the responsible editor. Must be an existing record in `AUTHORS` (`track-editorial`); no invented persons |
| `publishedAt`, `updatedAt`, `reviewedAt` | `publishedAt` | the date line ("Published", "Updated", "Last reviewed") and `datePublished`/`dateModified` |
| `takeaways[]` | yes | "Key takeaways" box above the body — 3 to 4 short sentences in the language of the file, plain text (no Markdown); the count is validated by `node apps/web/scripts/validate-knowledge-content.mjs` (editorial rules in `docs/14-knowledge-content-rules.md` §3). `MAX_TAKEAWAYS = 6` in `lib/knowledge-article.ts` is only a display cap, not the authoring rule |
| `sources[]` (`title`, `url`) | recommended | "Primary sources" section with the host next to each link; printed with the full URL |
| `legalNotice: true` | no | the "general information, not legal advice" note under the body |
| `coverAlt` | yes | alt text of the social card and cover |
| `featured: true` | no | the hub's lead story |

Reading time is computed from the body; do not write it into the front matter.

## 3. Body: headings and the table of contents

- Start the body with `##` (the h1 is the title). Use `##` for sections and `###` for sub-sections; both appear in the table of contents (sticky on desktop, collapsible on mobile). `####` and deeper are not listed.
- Anchor ids are generated by `rehype-slug` from the heading text (`## Three losses` → `#three-losses`, duplicates get `-1`, `-2`). Linking to a heading from another article is possible but ties the link to the heading text.
- Keep paragraphs short; the text column is limited to 65–75 characters per line. Bold the key term at the start of a paragraph instead of adding more headings.

## 4. Blocks

Everything below is plain Markdown/GFM or one of the named MDX components. There is no raw HTML in articles.

### Tables

GFM tables render with a scrolling container on narrow screens. Keep the first column a label and avoid more than five columns.

```md
| Signal | Browser | Server |
| --- | --- | --- |
| Purchase | pixel | Conversions API |
```

### Checklists

GFM task lists (`- [ ]` / `- [x]`) are editorial checklists, not forms: the template renders no checkbox control but a marker plus visually hidden localized state text ("To do: " / "Done: ", `checklist` in `lib/marketing-copy/knowledge-article.ts`) before the item, so axe finds no unlabeled form element and screen readers read the state.

### Steps

Wrap an ordered Markdown list in `<Steps>`; the list stays a real `<ol>` and gets circled numbers. Blank lines around the list are required.

```mdx
<Steps>

1. **Install the snippet.** Paste the tag into the `<head>` of every page.
2. **Confirm the first page view.** Open the event debugger and reload the site.
3. **Enable server-side delivery.** Add the destination and approve the change.

</Steps>
```

### Callouts: `Note`, `Warning`, `Privacy`, `Practice`

Four boxes with icon and localized default title (Note / Hinweis, Warning / Warnung, Privacy / Datenschutz, In practice / In der Praxis). `title="…"` overrides the title. Content between the tags is Markdown; keep blank lines around it.

```mdx
<Warning>

Do not send the same purchase from the browser and the server without an `event_id`; Meta counts it twice.

</Warning>

<Privacy title="Consent Mode">

The advertising identifiers only leave the browser when `ad_storage` is granted.

</Privacy>
```

Use `Warning` for things that break measurement or violate consent, `Privacy` for data-protection consequences, `Practice` for what to do in the product, `Note` for everything else. A page needs at most one callout per section.

### Code blocks

Fenced code with a language gets a language label and a copy button. `title="…"` in the fence meta shows a title (file name, endpoint).

````mdx
```json title="request.json"
{ "event_name": "Purchase", "event_id": "order-1001" }
```
````

### Diagrams

The SVG data-flow primitives from `@track-site/ui` are available as MDX components: `Diagram` (owns the `<svg>`, `width`/`height` define the viewBox, `title` makes it an image for assistive technology, `caption` renders a figcaption) and inside it `FlowNode`, `FlowEdge`, `ConsentGate`, `DestinationChip`, `SignalDot`. The information a diagram shows must also be in the text.

```mdx
<Diagram width={520} height={120} title="Browser and server both deliver the purchase; Track deduplicates it" caption="One order, two paths, one delivery per destination.">
  <FlowNode x={0} y={38} label="Website" sublabel="browser" />
  <FlowEdge from={{ x: 120, y: 60 }} to={{ x: 200, y: 60 }} arrow />
  <FlowNode x={200} y={38} label="Track" emphasis />
  <FlowEdge from={{ x: 320, y: 60 }} to={{ x: 392, y: 60 }} arrow />
  <ConsentGate x={410} y={60} state="granted" label="consent" />
  <DestinationChip x={440} y={44} width={80} label="Meta" status="ok" />
</Diagram>
```

Props are those of the primitives in `packages/ui/src/diagram.tsx` (`tone`, `emphasis`, `shape`, `arrow`, `dashed`, `state`, `status`, …). Only static values: MDX expressions such as `{variable}` are blocked by the pipeline.

### Links

- Internal links use locale-neutral paths (`/features/consent`, `/tracking-knowledge/some-slug`); the template adds the locale prefix.
- External links open in the same tab and get `rel="noopener noreferrer"`; in print the URL is appended.
- No "Blog" wording anywhere; the area is called Tracking Knowledge.

## 5. What the template adds automatically

Breadcrumbs (Track → Tracking Knowledge → topic → article), the meta line, the responsible editor block, reading time and progress bar, the table of contents, key takeaways, the primary-sources section, the topic-specific Track CTA (`CTA_BY_TOPIC` in `lib/knowledge-article.ts`, texts in `lib/marketing-copy/knowledge-article.ts`), related articles, the "Was this article helpful?" block and the print stylesheet. Feedback votes are stored anonymously as `{ translationGroupId, locale, helpful, createdAt }` in `knowledge_feedback` (migration `0005`); the page never shows totals.

Metadata per locale: title/description, self canonical, hreflang from the localized slugs of every published version, the generated 1200×630 social card as `og:image` with a localized `og:image:alt`, `twitter:card=summary_large_image`, `BlogPosting`/`TechArticle` and `BreadcrumbList` JSON-LD.

## 6. Checklist before setting `status: "published"`

1. Front matter complete (`topic`, `contentType`, `level`, dates, `takeaways`, `sources`, `coverAlt`), `author` is `track-editorial`.
2. Body starts with `##`; headings are unique enough to make stable anchors.
3. Claims about platforms link to a primary source.
4. Callouts and steps have blank lines around their content.
5. `pnpm --filter @track-site/web test` passes (content parity, loader and template tests).
